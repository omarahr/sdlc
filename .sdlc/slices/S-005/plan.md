## Approach
The product change is small and already proved in three rounds: add the `verify` and `attempt` rows to `TAILS` in `skills/sdlc/branches.py`. `state` exists since S-003, so R-008 needs only tests.
Per ADR-20261009-053059-decision-judge-S-005-23a9, R-093 moves to S-027. This slice does not change `integrator.md` and has no R-093 test.
The three fix rounds failed on one test only: T-R-119, a regex scan for push calls. Each round closed the reported push spellings, and the verifiers found new ones. This plan drops the regex scan.
The new R-119 check reads the scripts with the Python `ast` module. It checks the process and network boundary, not the spelling of a push. It has four parts. Part A: every process call and every network call in the scripts sits at a pinned site. Part B: every call to a pinned git or gh wrapper gives a constant program and verb, and only three reviewed calls use the verb `push`. A gh or glab call may read, but it may not create a pull request or merge request, and a `gh api` or `glab api` call may not write. Part C: `sdlc-loop.js` has no way to start a process or reach the network. Part D: the loop gives its verify branch builder only to the `verify-<profile>` agent and the `verify-collector` agent.
A new process call, a new network call, a verb built at run time, a new `push` call or a new gh or glab call site each changes a pinned set, so the test fails. A spec-required read, such as the `gh api` and `glab api` reads in `read_rules` (spec section 3), changes only a pin. It does not hit a ban. A human then reviews the new site and updates the pin. The spelling of the push does not matter.
The section "R-119 scope" below lists the forms that the check covers and the forms that stay seeds. ADR-20261009-062930-decision-judge-S-005-388e binds R-119 to that section and sets the refutation rule.
Per ADR-20261009-062918-decision-judge-S-005-7fbd, the state-writer moves R-093 to S-027 in the ledger before the gate. S-005 closes with R-008, R-009, R-010 and R-119.

## R-119 scope
Scanned files: every file under `skills/sdlc` and `hooks`, except the directories `test`, `fixtures`, `prompts`, `__pycache__` and `node_modules`. Today the scanned set holds 12 `*.py` files, 1 `*.js` file (`sdlc-loop.js`), 2 `*.json`, 1 `*.md` and 1 `*.html` file. A scanned file must have one of these five extensions. The test pins the exact list of `*.py` and `*.js` files. A new script file of another type (for example `*.sh`, `*.mjs`, `*.cjs`) fails the test.

The check covers these forms in Python scripts:
- Any call to `subprocess.*`, `os.system`, `os.popen`, `os.exec*`, `os.spawn*`, `os.posix_spawn*`, `os.fork*`, `pty.*`, `asyncio.create_subprocess_*`, under any import alias (`import subprocess as sp`, `from subprocess import run as r`).
- Any import of `ctypes`, `multiprocessing`, `pty`, `socket`, `ssl`, `http.client`, `urllib.request`, `requests`, `httpx`, `asyncio` (by `import` or `from`).
- Any call to `urllib.request.*`, `http.client.*` or `socket.*` (the network sites).
- Any call to `eval`, `exec`, `compile`, `__import__`, `importlib.*`, `getattr`/`setattr` with a process or network module as the first argument, and any `globals()` or `vars()` subscript call.
- A push through a pinned wrapper or a direct site, a gh or glab call that creates a pull request or merge request, or a `gh api` or `glab api` call that writes, in any spelling of the constant arguments: quoted with `'` or `"`, split over lines, with options before the verb, with implicit string concatenation, or with a `+` of two string constants. `push_guard.py` folds these to tokens before it reads the verb.
- A verb, program or option before the verb that is not a constant string. The call is then opaque, and an opaque call is a violation.
- The forge rule for gh and glab calls, through a wrapper or at a direct site with a list-literal argv. Each call is recorded as `(file, enclosing function, program, verb, constant path prefix)`, and the test pins that set. Reads are allowed. These forms are violations: the verbs `pr create` and `mr create`; a `gh api` or `glab api` call with `-X` or `--method` set to a value other than `GET` (any case), or set to a value that is not a constant; a `gh api` or `glab api` call with any of `-f`, `-F`, `--field`, `--raw-field` or `--input`; an `api` path whose constant parts hold `pulls`, `merge_requests` or `graphql`. The constant path prefix is the constant text before the first run-time part of the path (an f-string or a `+` with a name). An `api` path with no constant prefix is opaque.
- The graphql ban (ADR-20261009-063408-decision-judge-S-005-368d). Every `gh api` or `glab api` call whose constant path holds `graphql` is a forge violation. This applies with or without flags, and whatever the method or fields are. `push_guard.py` does not read the query text, and it does not tell a query from a mutation. It has no GraphQL parser. A later slice that needs a graphql read must first get an ADR. That ADR lifts the ban for one pinned `(file, function)` site only, and it adds a query-only test case. The general ban stays, and the mutation mutants in T-R-119e stay.
- A pinned wrapper name used as a value (assigned, passed, returned or stored), not called.
- A `shell=True` call, or a direct process call whose argv is not a list literal, outside the pinned direct sites.

The check covers these forms in `sdlc-loop.js`: any use of a banned identifier, in code or in strings. The banned identifiers are `require`, `import`, `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `child_process`, `process`, `globalThis`, `global`, `eval`, `Function`, `Deno`, `Bun`, `navigator`, `Worker`, `exec`, `execSync`, `execFile`, `execFileSync`, `spawn`, `spawnSync` and `fork`.

One allowlist applies. The exact single-quoted string literal `'global'` is allowed, and only that literal. Today the file has three of them, all in `decisionPanel`: the proposer label `${q.sliceId || 'global'}:${angle}`, the log line `decision panel for ${q.sliceId || 'global'} got no proposals`, and the judge label `q.sliceId || 'global'`. They are display labels for an escalation with no slice id. The scanner removes each `'global'` literal before the identifier match, and it reports the removed literals as `jsAllowed` with the line number and the trimmed line. The test pins `jsAllowed` at exactly these three sites. A fourth `'global'` literal changes the pin, so a human reviews it. A bare `global`, `global.x`, `global[...]` or a `"global"` in double quotes or backticks still matches the ban.

Today the file has no banned identifier outside the three allowed literals. I ran the ban regex on the current file: it matches only these three `'global'` literals, at lines 401, 404 and 408.

Refutation rule (ADR-20261009-062930-decision-judge-S-005-388e):
- A verifier refutes R-119 only with a literal form in a scanned file. The form must be inside the covered scope above. It must leave the `push_guard.py` output equal to the pins.
- A new form that is in neither list is covered when it is a process call or a network call in a scanned file. Such a form refutes R-119 when the output stays equal to the pins.
- Any other new form is a seed.
- The seeds S1 to S5 below are never refutations. The verifier records each seed that it finds in its report.

These forms stay seeds:
- S1. Data flow into a pinned site. Example: rebind the `run` variable before the reviewed run-branch push in `state-write.py` to a verify name. The state-write tests prove what these three sites push today.
- S2. Repository or environment state that changes what a constant git verb does. Examples: a git alias or hook written to `.git/config` by a pinned `config` call, `GIT_*` environment variables, a `.gitconfig` file.
- S3. Reaching a loader through attribute walks the scanner does not name: `this` in `sdlc-loop.js` (the file uses the word `this` in prose 20 times), `().__class__.__base__.__subclasses__()`, `sys.modules[...]`, `builtins` access.
- S4. Agents and prompts. An agent can push a branch that the loop names. R-119 covers the scripts, not agent prose. S-027 owns the prompt text.
- S5. Code outside the scanned file set: the `test`, `fixtures` and `prompts` directories, and tools outside the plugin.
